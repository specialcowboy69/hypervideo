# Workflow eXLSEY7Fzg0kGBit - HyperFrames Content Intake

## Purpose

`eXLSEY7Fzg0kGBit` turns a short `summary` payload into a review-gated
`data-lab` video draft.

The workflow is intentionally not a publisher. It creates a draft MP4, stores
review metadata, and requires an approval step before Reel scheduling can run.

## Current State

- n8n workflow name: `HyperFrames Content Intake`.
- n8n workflow id: `eXLSEY7Fzg0kGBit`.
- Current production state after the VPS deployment: inactive.
- Sanitized export: `n8n/hyperframes-summary-intake-workflow.json`.
- Backup examples live under `n8n/backups/`.

Do not activate this workflow casually. Activation exposes the webhook paths and
can generate paid ElevenLabs audio and remote renders when called.

## Webhooks

```text
POST /webhook/hyperframes-summary-intake
POST /webhook/hyperframes-video-review-approve
POST /webhook/hyperframes-video-review-reject
```

Expected intake payload:

```json
{
  "summary": "Resumen en espanol con la idea del video."
}
```

The summary should be long enough to support a 40-60 second video. The workflow
rejects empty or very short summaries before calling the AI node.

## High-Level Flow

```text
summary webhook
  -> Set Summary And Prompt
  -> Gemini JSON generation
  -> strict JSON validation and VPS command preparation
  -> SSH Run Data Lab Pipeline
  -> response with needs_review metadata
```

Review flow:

```text
approve webhook
  -> review-video-job approve
  -> schedule-instagram-reel

reject webhook
  -> review-video-job reject
  -> mark queue item needs_revision
```

## Runtime Contract

The VPS host is not treated as the Node.js runtime for this workflow. The SSH
nodes execute commands through the existing Docker image:

```text
n8n-hyperframes-renderer
```

The workflow mounts the deployed project into the container:

```text
/opt/n8n/hyperframes:/work
```

The summary pipeline also mounts uploads:

```text
/opt/n8n/hyperframes_uploads:/opt/n8n/hyperframes_uploads
```

This matters because host-level Node/npm/unzip availability must not be assumed.

## VPS Files

Project deployment:

```text
/opt/n8n/hyperframes
```

Important files:

```text
/opt/n8n/hyperframes/.env local
/opt/n8n/hyperframes/.env.n8n
/opt/n8n/hyperframes/scripts/run-data-lab-video-pipeline.mjs
/opt/n8n/hyperframes/scripts/review-video-job.mjs
/opt/n8n/hyperframes/scripts/trigger-n8n-build-render.mjs
```

Environment files should be mode `600`. Do not print or copy their values into
docs, screenshots, or chat.

## Script Responsibilities

- `scripts/ai-video-intake-schema.mjs`: normalize and validate AI JSON.
- `scripts/create-video-from-summary.mjs`: create pending video package and
  queue metadata.
- `scripts/run-data-lab-video-pipeline.mjs`: orchestrate package creation,
  ElevenLabs scene audio, remote render trigger, and review metadata.
- `scripts/review-video-job.mjs`: approve/reject review actions; approve calls
  `schedule-instagram-reel.mjs`.
- `scripts/patch-summary-intake-vps-runtime.mjs`: patch this workflow so SSH
  nodes use the Docker runtime and `.env.n8n`.

Template-only or builder-only changes do not require a workflow patch. Deploy
updated runtime files to `/opt/n8n/hyperframes` and validate inside
`n8n-hyperframes-renderer`. Patch this workflow only when prompt text, JSON
schema, node code, command shape, webhook behavior, or review/publication logic
changes.

## Queue Outcome

Successful draft generation should leave the item as:

```text
status: needs_review
review.status: needs_review
outputs.render: <R2 MP4 URL>
review.approve_url: <approval webhook URL>
review.reject_url: <reject webhook URL>
```

Approval is intended to be idempotent. Do not enqueue duplicate Reels for the
same slug.

## Known Deliberate Limits

- `video-queue.xlsx` is not automatically regenerated by Summary Intake V1.
- The workflow should stay inactive until an explicit activation and dry-run
  check are requested.
- End-to-end live generation can spend ElevenLabs/render resources.
- Approval can schedule real publication unless `dry_run` is used.
- Rejection marks the item as `needs_revision`; this is a review-cycle state,
  not final failure.
